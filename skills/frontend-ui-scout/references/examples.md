# Example task routing

These examples illustrate which directories to load, how much research to do, and when to stop. Names below refer to catalog entries, not verified individual components.

## Example: sports analytics dashboard

**Task:** Rework a dense statistics table and player profile dashboard.

- Inspect existing data model, responsive behavior, table controls, charting framework and design tokens.
- Read `02-application-ui.md` for Tremor, shadcn/ui and Kibo UI leads; read `03-design-inspiration.md` for Refero and Mobbin references.
- Compare specific tables, filters, KPI cards and mobile patterns; reject marketing effects that hurt legibility.
- Implement only if requested, preserving sorting, filters, accessibility and API data.
- Test long names, empty metrics, overflow and narrow screens.

## Example: memorable product landing page

**Task:** Make a hero section more impressive without generic glowing-gradient design.

- Read `01-component-marketplaces.md`, `06-templates-and-builders.md` and `03-design-inspiration.md`.
- Discover actual section demos and real sites, then choose a composition and one or two carefully integrated interactions.
- Prefer credible visual storytelling, typography and rhythm over dumping multiple unrelated animated widgets.
- Confirm small-screen motion and reduced-motion options.

## Example: CSS-only loading control

**Task:** Replace an awkward spinner in a plain HTML/CSS website.

- Inspect existing CSS, browser targets and reduced-motion settings.
- Read `04-css-and-generators.md`; research one or two exact CSS patterns.
- Avoid a React dependency for a single spinner.
- Test size, contrast, screen-reader status and slow-network behavior.

## Example: product onboarding

**Task:** Improve a multi-step athlete signup flow.

- Read `03-design-inspiration.md` for real onboarding UX references, then `02-application-ui.md` for forms and dialog components.
- Study step clarity, validation, progress, error recovery and mobile tap targets.
- Do not copy trademarked branding, screenshots or proprietary code from examples.
- Preserve backend validation and form submission behavior.

## Example: browsing unavailable

**Task:** Choose a website component without browser access.

- Inspect code and user-supplied screenshots. Use catalog homepages as provisional leads only.
- Say which external claims are unverified. Don't invent demo titles, dependency versions, release dates, prices or license permissions.
- If code implementation is authorized, first prefer in-repo components and run all locally available checks.
